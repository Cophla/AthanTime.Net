# Athan Time agent guide

Canonical engineering instructions for every AI agent. Read this, then
[product requirements](docs/REQUIREMENTS.md); load only task-relevant source/docs.

## Working rules

- Keep changes simple, explainable, offline-first and cross-platform. Prefer trusted free/open-source, business-usable .NET packages; no runtime network, accounts, API keys, paid tools or proprietary services.
- Prefer direct code and existing helpers over speculative abstractions, general-purpose frameworks or new dependencies. Use meaningful names for non-obvious values; keep comments about intent, ownership and platform limits. Simplify only with evidence that behavior, failure handling and platform coverage are preserved; do not rewrite working code merely to shorten it.
- Cross-platform capability is mandatory in every task and technical decision. Evaluate Windows, macOS and Linux across the declared target architectures for features, fixes, refactors, UI, dependencies/native libraries, runtime requirements, build tools, installers, updates/uninstall, signing, tests and documentation. Never silently narrow the supported platform/architecture matrix.
- Keep shared logic portable and guard OS-specific integrations explicitly. Preserve equivalent supported behavior or document the platform capability boundary. Check runtime/native-library availability before changing dependencies or target architectures; deployment and missing-runtime handling must account for each OS. Follow the verification rules below and report which platforms were actually checked and which remain unverified.
- Use scoped `rg`/`rg --files`. Do not load large bundled data/audio or generated `bin`, `obj`, `artifacts`, `TestResults`, `.vs`, `.location-cache` into context unless directly relevant.
- Use the local Git repository to inspect status/diffs before editing and preserve unrelated work. Track compressed offline data, media, provenance and tools together; keep extracted catalogs, generated outputs and user settings ignored. Respect `.gitattributes` for cross-platform line endings. Fresh-repository imports must use reviewed source without old `.git` metadata, private files or internal refs; preserve the original local repository. Add remotes or push only when the user requests it.
- Keep local IDE publish profiles (`*.pubxml`/`*.pubxml.user`), IDE/OS metadata, build/test outputs, diagnostic dumps/traces, caches and private signing material out of Git. Canonical deployment lives in the shared builder/packaging recipes, not local Visual Studio profiles. Never broadly ignore bundled databases, audio, icons, licenses or source tools. Untracking a local profile must preserve its file on disk. Keep `.editorconfig` and `.gitattributes` consistent: UTF-8 text, LF for shell/macOS launchers and CRLF for C#/Windows scripts.
- Before committing ignore changes, check generated/private example paths and required source/assets with `git check-ignore --no-index`; keep test procedures and bundled data/media/licenses visible across Windows/macOS/Linux.
- Before publication, inspect proposed refs/history as well as current files for secrets, private paths, user profiles, commit-author email and oversized blobs. Ignores do not remove previously committed content. Preserve required third-party attribution and public catalog provenance; do not mistake them for private user data. Publish only intended branches/tags, never local agent/internal refs. Record actual findings and limits instead of promising an exhaustive privacy guarantee.
- This file owns engineering rules; requirements own product behavior; specialist docs own procedures. Link instead of duplicating agent/vendor/memory guides. Preserve unrelated changes; remove only proven-unused in-scope code/files, never licenses/provenance/user data. Check XAML bindings, DI, JSON/resource loading, interface callbacks and linked builder sources before deleting; a text search or unused-member analyzer alone is insufficient. Merge related helpers when it improves navigation, retaining separate files for distinct responsibilities or shared build inputs.
- Default to constructor DI for testable logic. Register production services only in `Program.CreateHost`; owned UI editors/options are state, not separate services. Avoid needless abstractions, packages, timers and one-class-per-file splitting.
- .NET 10/Avalonia; top-level `Program.cs`. `Directory.Build.props` owns framework/version; `global.json` selects Microsoft.Testing.Platform, not an SDK version. Verify managed/native dependencies before .NET 11 upgrades.
- All packaging entry points read/delegate to the shared version and current-host architecture; avoid hard-coded fallback versions/CPUs. Preserve prerelease labels in UI, support drafts, filenames and setup display names; keep install/profile/single-instance identities stable across release channels. Native recipes enforce the matching OS; native macOS bundle versions use the three-component numeric base while display metadata retains the full release. Debian prereleases use `~` for ordering before their final version. Keep archive and native-package behavior distinct. See [release-channel packaging](docs/PACKAGING.md#beta-release-2026-11-03).
- Keep the current deployment direction: shared C# application and InstallerBuilder, per-OS self-contained packages, and the SoundFlow/NVorbis audio adapter with RID-matching native assets. Framework-dependent distribution and a custom universal installer are deferred; future deployment changes must address runtime prerequisites and native validation on all three OSes. See [deployment policy](docs/PACKAGING.md#deployment-policy).
- Serilog through `Microsoft.Extensions.Logging`; log applicable changes/failures, not every tick. No ad-hoc app console/file logging. Every configured sink needs its package; never restore a missing Console sink.
- JSON first for configuration/settings/transfers and small bundled data. Version `Data/locations.db.zip` as an ordinary Git object; the shared `LocationCatalog.targets` unpacks its prebuilt SQLite into configuration/RID-local `obj` only when missing/outdated and publishes it as `Data/locations.db`. Keep raw builder-output `Data/locations.db` ignored. Archived `locations.json.br` remains the builder/test reference, never a runtime full-catalog import. String comparisons/searches are `OrdinalIgnoreCase` unless explicitly linguistic; normalize deserialized string-key dictionaries. Persist culture-independent identities.
- Private fields `_privateCase`, protected `_PrivateCase`, public normal .NET naming. Concise XML summaries for public types/methods; explain non-obvious private logic.
- Every change must follow the [change completion rule](#change-completion-rule), including tests, comments, descriptions, engineering/AI instructions and other affected files. Handoff: changed behavior/files, checks actually run, remaining limits. Never report historical tests as newly run.

## Change completion rule

Before handing off **every change**, including fixes, refactors, packaging, data,
tests and documentation work:

- Review and update all affected unit/regression tests, comments/XML summaries,
  descriptions and help text, README/product requirements, specialist procedures,
  engineering rules and AI-agent instructions in the same task. Also check related
  configuration/defaults, all eight app translations, build/CI/installer/uninstaller
  files, licenses/provenance and generated assets when the change affects them.
- Keep this file as the canonical engineering/AI guide and link to it from other
  entry points; do not create duplicate rules or memory files. Keep descriptions
  and comments aligned with final behavior and actual platform support. Preserve
  the mandatory Windows/macOS/Linux review for every change.
- Add or update meaningful tests for changed behavior and failure cases; follow
  [verification](#verification), including Debug/Release checks and matching-OS
  native checks where applicable. Documentation-only work needs link/path and
  consistency checks, not artificial tests or production-code edits. Leave
  unaffected files alone; state material omissions or unverified checks in handoff.
- Review the final diff for stale text and unrelated changes. Record only checks
  actually run, with dated evidence and native/signing limitations. Rebuild affected
  generated assets or packages when their inputs change; documentation/test/comment
  edits alone do not require repackaging an unchanged application payload. Keep the
  artifact's recorded checksum and source/build evidence accurate.
- Include a simplicity review: remove only proven redundancy, retain necessary
  lifecycle/concurrency/platform safeguards, and avoid new abstractions without
  a concrete use. Check Git exclusions and editor/line-ending rules when adding
  generated outputs, tools or new file types.

## Accuracy invariants

- Adhan's MIT package owns astronomy/qibla. Never duplicate solar equations, alter presets to force a comparison, hide minute offsets or substitute city timetables. Sunni presets only; no Tehran/Jafari. Conventions choose method/Asr/high-latitude options, not corrections; official claims require specific authoritative evidence.
- Inject Noda Time embedded TZDB. Preserve IANA IDs, never OS rules/fixed country offsets; convert each event at its actual instant. Unexpected unknown zones log/fall back visibly and deterministically to UTC; manual input rejects invalid IDs. Keep original UTC instants for countdowns/reminders and elapsed-night midpoint. Future legal changes need an offline data release.
- Summer time defaults automatic; `SummerTimeOverrides` is per-zone and separate from prayer corrections. Recurring Gregorian rules use Noda Time date adjusters, local pre-change times, start-inclusive/end-exclusive, cross-year seasons and month-end fallback for unavailable days.
- Invalid loaded seasons stay visibly inactive, never automatic fallback; invalid drafts cannot apply. Preserve legacy forced-state behavior; missing `UseCustomSchedule` is false. Negative-savings normalization is display/manual-only; automatic civil clocks stay unchanged. Today uses actual status; other selected dates noon.
- `MinuteAdjustments` is the active copy of per-location `LocationMinuteAdjustments`, including sunrise, keyed by stable case-insensitive IDs. Schema 5 migrates old corrections only to the selected city; no carry-over to new cities. Hijri correction stays global.
- Location coverage is GeoNames `cities500`, not literally every settlement or every name translation. Do not invent unavailable translations/official algorithms; preserve provenance and documented fallback.
- Keep location lookup/search on demand with bounded query memory and independent read-only connections. The UI owns one active search worker and only the latest pending query/language; retain debounce, revision checks, UI-dispatch continuations and pending-work cleanup on clear/disposal. A running SQLite query finishes normally; never queue a worker per keystroke/language change. Generate SQLite and its search index offline using `tools/LocationDataBuilder`; share `LocationSearch` Unicode normalization rather than OS/SQLite case rules. Preserve two-character searches, literal wildcard input, ranking, stable IDs and translations. See the [data update procedure](docs/RELEASE-CHECKLIST.md#offline-data-updates).

## UI, persistence and reminders

- Summer-time edits are detached preview: Apply commits/recalculates, Cancel/location change discards, Restore automatic still requires Apply. Preserve drafts on translation/theme changes. Show committed status separately; failed saves remain visible/retryable.
- Keep caches bounded; invalidate prayer schedules for calculation inputs/date rollover, not language/theme/ticks. Ordinary ticks notify only changed display/seasonal values; keep independent draft/committed seasonal boundaries and second-accurate reminders. Reuse cached schedule scans and value identities instead of allocating filtered lists/strings per tick. Clear caches before import refresh. Measure resource changes with isolated before/after workloads, distinguish allocations from whole-process RAM/CPU/GPU, and never add machine-dependent timing thresholds or forced garbage collection. Detailed import/backup/reminder contracts are in [requirements](docs/REQUIREMENTS.md).
- `SettingsService`: same-directory temporary rename, validated backup, non-writing recovery Load; later Save may replace damaged primary. Reject future-schema downgrade and export over profile/backup/temp paths.
- Sticky profile warnings outrank transfer outcomes on every page. Import validates/resolves location before explicit confirmation; retain device startup/logging/history and reset pause/media/editor/interval state. Export includes coordinates/paths, not audio/logs; user reviews before sharing.
- Eight languages: `en ar fr es tr de id ur`; Arabic/Urdu RTL, others LTR, numeric inputs LTR. All captions live in `Data/ui-text.json`; do not restore a second C# translation catalog. New captions need all eight JSON entries. Preserve selector/row identities and values; notify both `Item`/`Item[]` for indexers. Test exact language/key parity and rendered text, not nonempty fallback; retain case-insensitive lookup, English fallback for unknown languages and visible unknown keys.
- Shoroq/sunrise is a time marker, never a prayer in user-facing captions or reminders. Preserve its optional before/at/after reminders, audio, corrections and persisted `Prayer.Sunrise` identity; keep it out of current/next-prayer countdowns. Product details stay in [requirements](docs/REQUIREMENTS.md).
- Center first startup; later restore the last normal main-window position from device-local `window-position.json`, clamping to display work areas or centering on the primary display when a monitor is missing. Do not persist minimized/maximized/fullscreen coordinates, transfer placement with settings or write on every drag event. Window-manager placement restrictions remain a native capability boundary. Keep readable light/dark controls at 980×600; six times visible at default 1180×800. Today first; Settings → Location / Prayer & clock / Audio & Adhkar / General. Use visibly bordered tabs with filled selection/focus indication, retaining native keyboard navigation and RTL.
- Ogg Vorbis only: NVorbis streams into SoundFlow/bundled miniaudio. No MP3/Opus/external player/full-file buffering. Native work off UI thread; release idle devices. Prayer audio has priority; skip busy/missed Adhkar, never queue catch-up playback/popups. Reuse the app clock; text is show → close → full pause.
- Persist 128 case-insensitive invariant Gregorian UTC reminder keys before dispatch; do not clear at midnight or fire early. After backward/>5-second gaps, reset Adhkar/hide stale text and skip events older than resume UTC; exact-resume events allowed. First ordinary startup may deliver unrecorded current-minute events. Pause/resume must not replay suppressed reminders.

## Desktop safety

- Confirm actual exit through one path; close-to-tray is not exit. Missing tray must leave the app accessible. Login startup is opt-in/current-user only: Windows Run, Linux XDG autostart, macOS LaunchAgent. Minimized startup may hide only on the first window opening; detach the startup handler before hiding. Tray Show/click must restore the same window repeatedly without reapplying startup preferences; test hide/restore cycles and the no-tray taskbar fallback.
- Route macOS shell/Dock `Reopen` events through the UI-dispatched restoration path too; Launch Services can reuse a process without invoking the duplicate-launch pipe client. Subscribe before framework startup completes, coalesce pre-window events and unsubscribe at desktop exit. Do not treat file/URI/background activation as reopen requests.
- Release startup acquires the per-user, cross-session single-instance guard and starts its same-user activation pipe before host/UI startup; retain the lease through host shutdown, including tray-only operation. A duplicate signals the primary window and exits before creating a host/profile/media; coalesce requests received before the first Opened/start-minimized handlers complete, then dispatch restoration on the UI thread. Bound all IPC waits; a denied/unavailable channel must never start another host. Stop activation at desktop exit without releasing the externally owned mutex until its acquiring thread disposes it after host shutdown. Preserve Windows foreground permission handoff and Unix socket path/user isolation. Debug development startup bypasses both guard and activation channel, allowing concurrent Debug runs and coexistence with Release. Runtime environment variables and diagnostic logging must never disable Release enforcement. Debug instances still share the per-user profile; do not add profile isolation or duplicate-reminder coordination implicitly. Use isolated names/processes in tests, never the production mutex. See [desktop requirements](docs/REQUIREMENTS.md#required-behavior).
- Ship one Release edition per OS. JSON `LoggingEnabled` controls files; `DebugLoggingEnabled` switches Information/Debug at runtime. Development/Release JSON are environment defaults, not user editions.
- Per-user `AthanTime/Logs`: disable closes sink/deletes only `athan-*.log`; remove directory only if empty, report failures. Never delete unrelated logs or user recordings.
- Support opens localized drafts in the user's mail app, never sends. `Application:SupportEmail` and the missing-setting fallback use the approved public project mailbox `athantimedotnet@gmail.com`; keep configuration, fallback, tests and release documentation aligned when it changes. This public contact is intentional, not a credential. Log export is app logs only, user-selected ZIP for review/manual attachment, never settings or custom Adhkar text.
- Keep offline data/license/translation updates reproducible; no runtime updater. See [release checklist](docs/RELEASE-CHECKLIST.md).
- Install/update must preserve the user profile, recordings and login preference. Windows uninstall uses the publish-generated exact payload list, never recursive removal of the install folder; a stale uninstaller must preserve another installation's shared registration/shortcut. Native integration procedures run only in a disposable desktop account/Sandbox; see [packaging procedures](docs/PACKAGING.md#installation-and-updates).
- Windows setup defaults to Only me without elevation; All users alone requests administrator permission. Always display the destination: prefilled/editable for fresh installs, retained/read-only for updates; Back to a fresh scope restores editing/browsing. Keep HKCU/32-bit-view user registration and HKLM/64-bit-view machine registration/shortcuts separate, retain each registered scope/folder on updates, and never reuse another scope's folder. The directory's installer-owned scope marker controls uninstall; missing legacy markers mean current user. Machine uninstall must not edit any user's profile or login entry. Linux DEB remains system-wide and macOS retains Applications-folder deployment.
- NSIS path validation must support not-yet-created destination directories and use scratch output so failures cannot clear `$INSTDIR`. NSIS consumes `/D=` before `$CMDLINE`; capture the native startup directory before assigning scope defaults. Verify real destination controls with the Sandbox-only `packaging/windows/Test-InstallerDestination.ps1`, never by running an installer against the host profile.
- Windows signing is optional build infrastructure for Windows-target binaries, including portable ZIP payloads. Preserve valid vendor signatures, sign managed/native code plus the NSIS uninstaller and setup, and fail requested signed builds on errors. Keep keys/passwords outside Git and never change security policy. [Windows signing](docs/WINDOWS-SIGNING.md) owns setup and validation limits.

## Source routing

App paths are under `AthanTime.Net/`; tools/tests/docs are repository-relative.

- `Program.cs`, `App.axaml.cs`: DI/host, deferred window factory, tray/desktop lifecycle and UI-dispatched duplicate activation; `Services/SingleInstanceGuard.cs` owns the pre-host Release lease/same-user pipe and Debug startup exception.
- `Models/`: `PrayerModels.cs` presets/schedules, `AppSettings.cs` schema, `LocationInfo.cs` places.
- `Services/`: `PrayerCalculator.cs` Adhan adapter; `TimeZoneService.cs` TZDB/rules; `SettingsService.cs` migration/recovery/transfer; `Data/default-settings.json` defaults.
- `Services/`: `LocationRepository.cs`, `ManualLocationService.cs`, `PrayerConventionRepository.cs` search/coordinates/conventions; `LocalizationService.cs` + `Data/ui-text.json` languages.
- `ViewModels/`: `MainViewModel.cs` state/reminders/import; `MainViewModel.MediaLocations.cs`, `MainViewModel.TextAdhkar.cs`, `SummerTimeRuleEditor.cs` owned editors/drafts.
- `MainWindow.axaml`, `MainWindow.axaml.cs`: navigation/UI-only handlers; `Styles/AppStyles.axaml` owns shared application appearance. `AppWindow.cs` owns secondary-window appearance/card framing and the prayer popup; `TextAdhkarWindow.cs` owns the non-activating reading popup. Use the shared theme/base for new app-owned windows.
- `Services/AudioPlayer.cs` owns `IAudioPlayer`, `AudioPlayer`, the streaming `VorbisAudioProvider` and `BundledAudio` paths; keep decoder sample/EOF/seek/disposal tests device-free. `AdhkarSchedulers.cs` and `DefaultAdhkarRepository.cs` retain scheduling/content responsibilities; [audio help](docs/AUDIO.md) and `THIRD-PARTY-NOTICES.md` own deployment/provenance caveats.
- `Services/`: `Logging.cs`, `LoginStartupService.cs`, `SupportService.cs` privacy-sensitive integrations.
- `Services/WindowPositionService.cs` owns the device-local position file and pure work-area geometry; `MainWindow.axaml.cs` tracks normal positions and desktop lifecycle events. Persist on hide/close/deactivation, retry failed saves, and keep monitor/DPI and tray restoration covered by isolated tests.
- `tests/AthanTime.Tests/`: pure xUnit v3/`Xunit.DependencyInjection`; `UiTestHost.cs` serialized headless UI, `ViewModelHarness.cs` injected fakes.
- `tools/LocationDataBuilder/` owns GeoNames JSON/SQLite/ZIP regeneration and `LocationCatalog.targets` incremental build extraction; `Services/LocationSearch.cs` shares Unicode normalization with the builder. Track both compressed inputs, never depend on a raw catalog in a source checkout. [Accuracy comparison](docs/ACCURACY-COMPARISON.md) owns dated Sidon reference/corrections.
- `Assets/athan-icon.svg` and `athan-icon-small.svg` are the editable artwork/desktop icon sources; `tools/IconBuilder/` generates the tracked PNG/ICO. Use `App.CreateDesktopIcon` for native icons and follow [icon regeneration notes](AthanTime.Net/Assets/ICON.md); keep rendering dependencies out of the app.
- Root `Create-Installers.cmd`/`.command`/`.sh`, `tools/InstallerBuilder/`, `packaging/`: launchers/.NET entry point/free OS recipes; `packaging/common.sh` shares direct Bash version/host defaults. `Directory.Build.targets` owns optional Windows build-output signing. [Packaging](docs/PACKAGING.md) owns prerequisites, usage and dated validation evidence. Optional `.github/workflows/desktop-validation.yml` builds five matching RIDs; private-repository runs remain disabled to avoid billing.

## Verification

For app changes run both configurations:

```powershell
dotnet build AthanTime.Net.slnx
dotnet test AthanTime.Net.slnx --no-build
dotnet build AthanTime.Net.slnx -c Release
dotnet test AthanTime.Net.slnx -c Release --no-build
```

- Pure xUnit.net v3/Microsoft.Testing.Platform with constructor DI; ordinary tests use `Avalonia.Headless`, never a second xUnit framework. Inject clocks/fake audio/login, temporary settings/log folders. Never touch real profiles/Run keys/autostart/LaunchAgents.
- Calculation changes need dated/location-specific regressions. Cover all-city zones, recurring/half-hour/negative seasons, UTC durations; persistence changes need migration/recovery/failure/import cases. Normal interval tests use one-second ticks; test gaps separately.
- Location changes need archived-JSON search/field comparisons and all-city TZDB checks against the shipped SQLite catalog. Include real accented/non-Latin inputs and known nonempty matches so two empty result sets cannot pass as translation coverage. Keep full-catalog reference loading in tests only; avoid machine-dependent timing/memory thresholds in unit tests. Run Debug and Release tests sequentially to avoid test-runner handshake collisions.
- UI tests select the relevant tab before visual-descendant assertions. Check every language/theme, stable values, rendered captions and numeric sizing. Normalize both transformed corners for RTL bounds.
- For startup work, measure built-app initialization separately from IDE builds/debugger attachment and first-run effects. Use isolated profiles/fake native integrations, retain exact measurement boundaries and host details, and never turn local timing samples into unit-test thresholds. See [startup evidence](docs/PACKAGING.md#startup-investigation-2026-10-23).
- Packaging tests use `InstallerPlan` or fake recipe commands, never OS installers. Verify a clean source-only build, incremental/missing/changed/invalid catalog extraction and archive-to-payload hash parity. Fresh staging; retain Ogg/NVorbis/RID miniaudio guards plus `Data/locations.db`, managed SQLite and RID-matching `e_sqlite3` guards. Bundle SQLite native libraries for all five supported RIDs; never require system SQLite. No trimming/single-file publishing without native revalidation.
- Native install/audio/tray/file picker/email/login needs matching-OS smoke tests. Cross-OS ZIPs are not native installers; CI is not certification. Windows 10 is best effort, not blanket vendor support. Record exact OS/architecture/versions and unverified checks in packaging docs.
- Docs-only changes: check links, paths and consistency; do not claim build/tests were rerun.
